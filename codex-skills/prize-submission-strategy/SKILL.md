# Prize Submission Strategy

Use this skill when a project needs both scientific credibility and product
pitch readiness.

## Principle

Do not optimize for a prize before the evidence exists. Optimize for the
reviewer's confidence: clear problem, measurable delta, reproducible artifact,
and honest limitations.

## Workflow

1. Split packets.
   - Research packet: paper, experiments, baselines, ablations, artifact guide.
   - Product packet: pitch story, demo flow, market, business model, compliance.
   - Keep venue-specific files outside the executable artifact when possible.

2. Define the claim-evidence matrix.
   - Each claim needs a command, table, figure, or test.
   - Unsupported claims should be removed or reframed as future work.

3. Build judge/reviewer stories.
   - Problem before the project.
   - What changed because of the project.
   - Why the result is not a black box.
   - What is not claimed.

4. Prepare demo proof points.
   - One-command run.
   - Visible data readiness.
   - Operational workflow.
   - Audit trail.
   - Reproducible metrics.

5. Avoid prize-killing tells.
   - Hype adjectives.
   - Venue names inside the runtime artifact.
   - Fabricated rigor or empty folders.
   - Screenshots without runnable evidence.
   - Claims of superiority without baselines.

## Evaluation Heuristic

If a judge asks "why should I trust this?", the app and packet should answer
without requiring the author to explain it live.
